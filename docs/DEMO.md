# 발표 진행안

## 기본 2분 시연

1. PC에서 경량 자율 제어, 규칙 기반 Agent, 2×를 선택합니다. “이 화면은 시설 모델, 대응 판단, 로봇·설비 행동을 연결합니다.”
2. 설비 과열을 실행합니다. CH-02의 경보 표시와 Agent의 센서 교차 확인을 짚습니다. “온도 신호 하나만으로 제어하지 않고 독립 관측을 비교합니다.”
3. 로봇이 움직이기 시작하면 통로 차단을 누릅니다. 경로와 실행 기록을 보여줍니다. “현장 조건이 달라지면 위치와 통행 가능 구역으로 경로를 다시 계산합니다.”
4. 현장 관측 후 **Agent → 현장 사진 도착**을 눌러 장비 사진을 크게 보여줍니다. “규칙 기반 Agent도 로봇이 도착한 위치의 가상 카메라 사진과 온도·판정을 웹에 보고합니다.” 사진을 닫고 환기가 올라가며 온도가 내려가는 모습을 설명합니다. “사진은 촬영 시점의 기록입니다. 점선은 조치하지 않은 예시 열모델이며, 현재 그래프로 조치 결과를 확인합니다.”
5. 대응 리포트를 열고 실행 기록, 이동 거리, 경로 변경, 검증 결과를 보여줍니다.
6. 센서 오류를 실행합니다. “센서 신호는 높지만 열화상은 정상입니다. 이 경우 환기를 높이지 않습니다.”
7. 통신 단절을 실행하고 정지를 확인한 뒤 연결 복구를 누릅니다. “상위 명령이 끊기면 로봇은 정지하고 재확인 후 이어갑니다.”

통로 생성은 로봇이 해당 위치에서 2.1m 안에 있으면 보류됩니다. 로봇 바로 위에 장애물이 갑자기 생성되는 시연을 피하기 위한 조건입니다.

## 기술 시연 추가

### 웹에서 지시하고 정상일 때 자율 복귀

1. **Go1 자율 점검**에서 CH-02와 **정상 예시**를 선택합니다. 정밀 보행을 보여주려면 먼저 **Go1 보행정책 · 정밀**을 준비합니다.
2. **CH-02 점검 보내기**를 누릅니다. 3D 화면에서 선택한 장비의 **이 장비 점검 보내기** 버튼도 같은 임무를 시작합니다.
3. 현장 도착 후 웹의 온도 센서·열화상·관측 차이를 짚습니다. “도착 전에는 관측 전, 도착 후에는 두 관측을 비교한 판정을 보고합니다.”
4. **정상 판정 · 자동 복귀 완료**를 확인합니다. “정상일 때는 별도 지시 없이 도킹 위치로 돌아옵니다.”
5. **CH-02 과열 예시** 또는 **CH-02 센서 오류 예시**로 다시 점검합니다. “이상을 발견하면 현장에서 대기하며 보고를 남깁니다.” **보고 확인 · 복귀 지시**를 누르면 돌아오고 이상 판정은 유지됩니다.

웹 점검은 공개 데모와 모바일에서도 브리지 없이 사용할 수 있습니다. 텔레그램으로도 보고받으려면 localhost에서 **임무 진행 자동 보고**를 켭니다. 스마트폰에서 접수한 점검은 기존처럼 결과를 보고한 뒤 복귀합니다.

### 보행 정책과 로컬 Agent

- Go1 보행정책 · 정밀을 선택하고 모델 준비를 기다립니다. 로봇 추적 카메라에서 보행을 보여줍니다. “공개 보행 정책이 관절 명령을 만들고 MuJoCo가 접촉과 움직임을 계산합니다. 시설 경로는 A*입니다.”
- 로컬 Agent 브리지를 실행하고 Codex 또는 Hermes를 선택합니다. “설치된 CLI가 이 관측 JSON을 받아 점검 계획과 이유를 반환합니다. 허용된 계획과 실행 제약은 코드가 검증합니다.”
- JSON 리포트에는 실제 선택한 Agent·로봇 모드, 관측값, 실행 시각, 도구 이름, 정책 추론 횟수가 포함됩니다.

## 텔레그램으로 Go1 보고 시연

로컬 브리지를 실행하고 웹 화면의 **텔레그램**에서 봇·대화방과 **전송 준비됨** 표시를 확인합니다. 휴대폰에는 기존 Hermes 봇의 대화방을 열어둡니다.

1. **연결 테스트**를 보내 실제 대화방에 가상 Go1의 메시지가 도착하는 모습을 보여줍니다.
2. **임무 진행 자동 보고**를 켠 뒤 Go1 정밀 모드에서 시나리오를 실행합니다. “같은 실행 ID로 경보, Agent 판단, 로봇의 현장 관측과 조치 결과가 전달됩니다.”
3. 로봇이 복귀하면 **대응 요약**을 보내 판단·검증 결과와 정책 추론 횟수를 설명합니다. “이 값은 방금 실행한 브라우저 시뮬레이션 기록입니다.”
4. 시연 후 자동 보고를 끕니다.

수신 메시지와 웹의 미리보기에는 가상 Go1·브라우저 시뮬레이션 표시가 포함됩니다. 텔레그램은 실제로 발송되며, 공개 웹 데모에서는 미리보기만 제공합니다. 자세한 설정은 [텔레그램 안내](TELEGRAM.md)를 참고하세요.

## 스마트폰 지시로 현장 점검

1. 노트북에서 Go1 정밀 모드를 준비합니다. 텔레그램 패널에서 **CH-02 과열 예시**와 **스마트폰 명령 받기**를 선택합니다.
2. 스마트폰의 기존 Hermes 대화방에 `Go1 CH-02 점검해줘`를 보냅니다. 접수 응답과 웹의 로봇 이동을 동시에 보여줍니다.
3. 현장 도착 후 온도·열화상 관측과 **과열 의심** 보고를 설명합니다. “이 명령은 이상 유무를 점검하며, 환기 조치는 별도 대응 임무에서 실행합니다.”
4. Go1이 복귀하면 같은 실행 ID의 결과 보고를 확인합니다.
5. `Go1 공조 유닛 점검해줘`로 정상 장비의 점검과 비교합니다. 실행 중 `Go1 상태` 또는 `Go1 정지`로 진행 확인·중지를 보여줄 수 있습니다.
6. 웹에서 과열 점검을 시작해 현장 대기까지 진행한 뒤 스마트폰에서 `Go1 복귀`를 보냅니다. “점검을 웹에서 시작해도 스마트폰에서 복귀를 지시할 수 있습니다.” 명령 접수·실행 확인·도킹 완료의 Telegram 보고를 순서대로 확인합니다. 이동 중 지시하면 현장 점검 미완료로 보고하며 돌아옵니다.

## 스마트폰 음성으로 고원 호출

1. 노트북에서 Go1 정밀 모드를 준비하고 **스마트폰 명령 받기**를 켭니다.
2. 기존 Hermes 봇 대화방의 마이크로 “고원아, 공조 유닛 점검해줘”라고 말합니다. 인식 문장이 표시되고 웹 로봇이 AHU-01로 이동하는 모습을 보여줍니다.
3. 정상 판정과 자동 복귀를 확인합니다. “음성은 이 PC의 한국어 Whisper가 인식하고, 고원을 Go1의 허용 명령으로 연결합니다.”
4. 웹에서 CH-02 과열 점검을 시작해 현장 대기 상태로 만듭니다. “고원아, 상태 알려줘”, “고원아, 정지해줘”, “고원아, 복귀해줘”를 차례로 말해 상태 보고와 정지 후 복귀를 보여줍니다.
5. 시연 후 명령 받기를 끕니다. 설정·음성 인식 한계는 [텔레그램 안내](TELEGRAM.md)를 참고합니다.

## 정부사업·기업 논의에서 연결할 질문

| 검증할 가설 | 실증 데이터 | 다음 구현 |
|---|---|---|
| 교차 관측으로 불필요한 출동·제어 감소 | 온도·열화상·점검 이력과 실제 판정 | ICTWAY 설비 ID·상태 수집 어댑터 |
| 현장 조건 변화에 대응하는 점검 임무 | 경로, 장애물, 정지·복구 이력 | 실제 로봇 인터페이스와 승인 경계 |
| 학습 정책의 현장 적용 가능 범위 | 충돌·완료율·에너지·지연 분포 | 시뮬레이션 무작위화와 정책 평가 |
| 초파리 뇌 기반 감각 통합의 장점 | 동일 입력·계산 예산에서 비교 | 커넥톰 모델과 표준 정책의 비교 실험 |

실증 효과·성능 수치는 현장 데이터로 측정해야 합니다. 현재 온도 변화나 시뮬레이션 시간은 사업 성과 지표의 실측값으로 제시하지 않습니다.
