# 발표 진행안

## 기본 2분 시연

1. PC에서 경량 자율 제어, 규칙 기반 Agent, 2×를 선택합니다. “이 화면은 시설 모델, 대응 판단, 로봇·설비 행동을 연결합니다.”
2. 설비 과열을 실행합니다. CH-02의 경보 표시와 Agent의 센서 교차 확인을 짚습니다. “온도 신호 하나만으로 제어하지 않고 독립 관측을 비교합니다.”
3. 로봇이 움직이기 시작하면 통로 차단을 누릅니다. 경로와 실행 기록을 보여줍니다. “현장 조건이 달라지면 위치와 통행 가능 구역으로 경로를 다시 계산합니다.”
4. 점검 후 환기가 올라가고 온도가 내려가는 모습을 설명합니다. “점선은 조치하지 않은 예시 열모델입니다. 조치 결과를 관측으로 다시 확인합니다.”
5. 대응 리포트를 열고 실행 기록, 이동 거리, 경로 변경, 검증 결과를 보여줍니다.
6. 센서 오류를 실행합니다. “센서 신호는 높지만 열화상은 정상입니다. 이 경우 환기를 높이지 않습니다.”
7. 통신 단절을 실행하고 정지를 확인한 뒤 연결 복구를 누릅니다. “상위 명령이 끊기면 로봇은 정지하고 재확인 후 이어갑니다.”

통로 생성은 로봇이 해당 위치에서 2.1m 안에 있으면 보류됩니다. 로봇 바로 위에 장애물이 갑자기 생성되는 시연을 피하기 위한 조건입니다.

## 기술 시연 추가

- Go1 보행정책 · 정밀을 선택하고 모델 준비를 기다립니다. 로봇 추적 카메라에서 보행을 보여줍니다. “공개 보행 정책이 관절 명령을 만들고 MuJoCo가 접촉과 움직임을 계산합니다. 시설 경로는 A*입니다.”
- 로컬 Agent 브리지를 실행하고 Codex 또는 Hermes를 선택합니다. “설치된 CLI가 이 관측 JSON을 받아 점검 계획과 이유를 반환합니다. 허용된 계획과 실행 제약은 코드가 검증합니다.”
- JSON 리포트에는 실제 선택한 Agent·로봇 모드, 관측값, 실행 시각, 도구 이름, 정책 추론 횟수가 포함됩니다.

## 정부사업·기업 논의에서 연결할 질문

| 검증할 가설 | 실증 데이터 | 다음 구현 |
|---|---|---|
| 교차 관측으로 불필요한 출동·제어 감소 | 온도·열화상·점검 이력과 실제 판정 | ICTWAY 설비 ID·상태 수집 어댑터 |
| 현장 조건 변화에 대응하는 점검 임무 | 경로, 장애물, 정지·복구 이력 | 실제 로봇 인터페이스와 승인 경계 |
| 학습 정책의 현장 적용 가능 범위 | 충돌·완료율·에너지·지연 분포 | 시뮬레이션 무작위화와 정책 평가 |
| 초파리 뇌 기반 감각 통합의 장점 | 동일 입력·계산 예산에서 비교 | 커넥톰 모델과 표준 정책의 비교 실험 |

실증 효과·성능 수치는 현장 데이터로 측정해야 합니다. 현재 온도 변화나 시뮬레이션 시간은 사업 성과 지표의 실측값으로 제시하지 않습니다.
