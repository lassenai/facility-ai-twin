## 텔레그램 실제 발송과 화면 검증

기존 Hermes 봇과 기본 개인 대화방으로 **7건의 실제 발송 성공 응답**을 확인했습니다. 시험 메시지 1건, 센서 오류 임무 이벤트 5건, 완료 후 대응 요약 1건입니다. Telegram 메시지 ID와 수신 대화방이 일치한 응답을 발송 성공의 근거로 사용했습니다. 사용자의 메시지 열람 여부는 확인하지 않았습니다.

정밀 Go1 + MuJoCo에서 센서 오류 점검과 복귀를 완료했습니다. 해당 실행의 보고에는 환기 35% 유지, 모델 온도 38.4°C, 시뮬레이션 43.6초, 이동 21.53m, 보행 정책 추론 2,182회가 포함됐습니다. 보고는 동일 runId로 연결됐으며 모든 메시지에 가상 로봇·브라우저 시뮬레이션임을 표시했습니다.

외부 발송을 모의 응답으로 대체한 별도 브라우저 검증에서는 아래 항목을 확인했습니다.

- 과열의 경보 → Agent 분류 → 이동 → 현장 관측 → 환기 85% 조치 → 검증 → 복귀 보고 7건의 순서와 실제 관측값.
- 현재 임무의 대응 요약 전송 및 전송 기록 표시.
- 자동 보고를 끄면 아직 요청하지 않은 이벤트 보고를 취소. 이미 진행 중인 요청은 완료.
- 실패 표시, 자동 보고 중지, 자동 재전송 없음.
- 지원하는 localhost 호스트 밖에서는 발송·자동 보고가 비활성화되고 브리지 요청이 발생하지 않음.
- PC 1440px와 모바일 390px에서 패널·미리보기 표시, 모바일 가로 넘침 없음, 확인한 흐름의 페이지 실행 오류 0건.

최종 기능에 추가한 Agent 분류·환기 조치 이벤트는 자동 테스트와 모의 HTTP 응답을 사용하는 브라우저 흐름으로 검증했습니다. 기존 Hermes의 수신 방식과 설정은 변경하지 않았습니다.

## 스마트폰 Go1 명령 연결 검증

Hermes의 `facility-go1` 확장을 기존 홈의 plugins에 설치·활성화하고 기본 gateway를 정상 종료 후 재시작했습니다. `hermes plugins doctor facility-go1 --ci`에서 manifest·런타임 탐색·Python import·hook 등록을 통과했습니다. 기존 봇 토큰·대화방·다른 프로필 gateway는 변경하지 않았습니다. Go1 수신 경로만 추가했으며 별도의 Telegram 수신 폴링을 시작하지 않았습니다.

Hermes 메시지 이벤트 형태의 시험 명령을 수신 확장에 주입해 **확장 → 실제 로컬 브리지 → 브라우저 Go1 → 실제 Telegram 발송** 흐름을 확인했습니다. 스마트폰에서 사람이 직접 입력하는 단계는 이 검증에 포함하지 않았습니다.

- 정밀 Go1의 CH-02 과열 점검과 복귀: 39.26 시뮬레이션 초, 이동 21.53m, 정책 추론 1,963회, 넘어짐 없음.
- 온도 센서 64.2°C와 열화상 63.8°C로 `과열 의심` 판정. 환기 35% 유지. 고장 해소나 정상 복구로 표시하지 않음.
- 점검 접수·현장 판정·복귀 요약 **3건의 실제 Telegram 성공 응답**, 웹 전송 기록과 발송 수 일치.
- 렌더링 루프와 1초 주기의 실제 상태 전송으로 진행. 최종 실행에서 상태 요청의 최대 간격 약 1.82초. 초기 실행 지연을 허용하도록 연결 확인 유효시간 30초를 적용.
- 모의 Telegram 응답을 사용하는 별도 브라우저 흐름에서 정상 AHU-01 점검, CH-02 센서 불일치, 명령에 따른 정지와 위치 유지 확인.
- 모바일 390px 가로 넘침 없음, 최종 실행의 페이지 오류 0건.

브라우저 연결이 끊긴 시험에서는 완료 보고 대신 확인 필요 안내를 보냈습니다. 임무 수락과 실제 완료·전송 성공을 별도로 기록합니다. 테스트용 브리지는 종료했습니다.

## 웹 자율 점검과 정상 판정 시 자동 복귀

- 정상 장비 5종에서 현장 관측·판정 후 도킹 위치로 자동 복귀하고, 충돌 여유 폭을 유지하는 단위 테스트 통과.
- 과열·센서 불일치·확인 불가 판정은 `await_review`에서 주행 명령 0으로 대기. 복귀 지시 전 완료로 표시하지 않음.
- 복귀 지시는 일시정지·연결·배터리 제약을 확인하며, 복귀 후에도 이상 판정과 환기 설정을 유지.
- 실제 브라우저 정밀 Go1 정상 점검: 39.26 시뮬레이션 초, 21.53m 이동, 1,963회 정책 추론. 별도 복귀 클릭 없이 도킹 완료, 넘어짐 없음.
- 정밀 Go1 과열 점검: 센서 64.2°C·열화상 63.8°C를 보고하고 현장에서 대기. 실제 렌더링으로 3초 관측 중 위치 변화 0.12m 미만. 보고 확인 후 복귀 완료, 환기 35% 유지, 넘어짐 없음.
- 정밀 모드 연속 점검에서 정책 추론 횟수를 각 임무의 경과 시간과 대조. 첫 임무 1,963회, 두 번째 임무 2,029회로 별도 기록하며 물리 엔진의 누적 3,992회와 구분.
- 웹 센서 불일치 점검의 자동 Telegram 보고는 모의 응답 6건으로 확인. 이 웹 기능 검증 중 외부 Telegram 발송 없음.
- Telegram 명령 받기를 끄더라도 웹에서 시작한 점검은 중단하지 않음. 스마트폰에서 시작한 임무의 기존 보고·복귀 정책 유지.
- 390px 모바일 화면에서 PU-01 선택·점검·정상 자동 복귀 실행. localhost 외의 웹 진입에서도 브리지 없이 점검 사용, 가로 넘침 없음. 확인한 흐름의 페이지 오류 0건.

## Telegram 복귀 명령

- `Go1 복귀`, `Go1 복귀해줘`, `Go1 돌아와`, `/go1 return`의 고정 명령 해석 확인. 부정·쉘 구문·추가 장비 ID는 실행하지 않음.
- 웹 점검에서 대기 중인 Go1을 동일 실행 ID·장비 ID에 묶어 복귀시키고, 접수만으로 실행 또는 완료를 보고하지 않는 테스트 통과.
- 연결 단절·배터리 부족·처리 중인 정지 명령은 복귀를 보류하며 이후에 자동 실행하지 않음. 다른 실행이나 복귀하지 않은 상태를 완료로 확인하지 않음.
- 정밀 Go1 웹 과열 점검에서 Hermes 메시지 이벤트 형태의 `Go1 복귀`를 수신 확장에 주입해 **확장 → 실제 브리지 → 웹 Go1 → 실제 Telegram** 흐름 확인. 스마트폰에서 사람이 입력한 단계는 포함하지 않음.
